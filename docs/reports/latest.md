## Housekeeping done

1. **Dev-tool guard.** `dev:scrape` and `dev:fixtures` call `assertLocalDatabase` (`apps/server/src/dev/local-only.ts`) and refuse to run unless `DATABASE_URL` is a `postgres://` URL whose host is `localhost` or `127.0.0.1`, with an error that says what to set. Only the parsed host counts, so `localhost.example.com`, `postgres://localhost:pw@prod.example.com/x` and a `?host=` / `?hostaddr=` override (libpq honours those) are all refused. 14 tests in `apps/server/test/dev-guard.test.ts`. Checked by hand: a remote URL stops `dev:scrape` with the error; a local one still runs.

Checked: after setting the Gradle heap to 4096 m by hand, `expo prebuild` wrote both caps back. 2 tests in `apps/mobile/__tests__/gradle-memory.test.ts`.

## Tile hosting options for MapLibre

1. **OpenFreeMap** (public instance): free, no key, no registration, unlimited views, commercial use allowed, donation-funded, **no SLA**. Fastest start. Risk: a free service with no guarantee. Mitigation: the style URL lives in app config (and later the server), so we can move without an app update.
2. **Protomaps PMTiles on Cloudflare R2**: we host one Serbia extract, update it monthly, serve it with range requests (CORS for `GET`, `HEAD` and the `range` header). Cheap (about $0–5 / month at our size), we control logs and availability. It costs us the extract pipeline and a little ops. **To verify in a spike:** that MapLibre Native in the React Native library reads PMTiles directly on Android, or whether we need a tiny proxy.
3. **MapTiler Cloud**: hosted and supported, but the free plan is non-commercial; Flex starts at $30 / month and grows with sessions.

## What I would pick, and what I would verify first

Your lean is MapLibre, and I agree: it keeps us out of Google's identifier and billing account, looks the same on both platforms, and draws our GeoJSON directly. I would start on **OpenFreeMap** with the style URL in config, and keep **Protomaps on R2** as the move if its missing SLA ever matters. Before building, a one-day spike on the emulator would settle: (a) the library renders on RN 0.88 with the new architecture and our path workaround, (b) the APK size it adds, (c) a Latin / Cyrillic label switch and a dark style, (d) PMTiles on Android, (e) the OpenFreeMap privacy policy for the Data safety form.

If you choose Google instead: a Google Cloud billing account, a restricted key (package + SHA-1 of the debug, upload and Play App Signing keys), the Data safety entries above, and a different look on iOS.
