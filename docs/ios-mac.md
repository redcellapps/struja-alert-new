# iOS: what compiles on Windows, and what is left for the Mac (**[MAC]**)

`expo run:ios` is not possible on Windows. Step 12 of Phase 3 therefore checks only that the iOS code paths **compile**; the iOS smoke build and everything marked **[MAC]** belongs to Phase 6, on a Mac with the Apple Developer account.

## What is checked on Windows

| Check                                                 | How                                                                                                                                                                                                                                                          |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| TypeScript resolves `.ios` files and the iOS branches | `pnpm typecheck` runs `tsc -p tsconfig.json` and then `tsc -p tsconfig.ios.json` (`moduleSuffixes: [".ios", ".native", ""]`); it already found one real error (a platform file importing itself)                                                             |
| The whole app bundles for iOS                         | `pnpm --filter @struja/mobile bundle:ios` (`expo export --platform ios`, Metro and Hermes, no Xcode): 2173 modules, 5.5 MB of bytecode, into the git-ignored `.dev/ios-bundle`                                                                               |
| The iOS branches do the safe thing                    | `apps/mobile/__tests__/ios-paths.test.tsx`: no calendar button and no Android intent, notification permission reported as undetermined, 44 pt touch target, the iOS tab bar leaves the bar to the system, and every `.ios.*` file carries a **[MAC]** marker |

The bundle identifier is `rs.strujaalert.app` in `apps/mobile/app.json` (`ios.bundleIdentifier`), the same as the Android application id.
